# v0.1.0

The first release of zen-review.

It answers one question a diff viewer cannot: which of these machine-generated
changes have I inspected, and are they still the ones I inspected. What you have
read is stored as line ranges and carried through every new version of the
changeset, so a rewrite hands back the parts it destroyed rather than leaving a
stale mark on code nobody read.

## What it does

- **One changeset.** The merge base with your base branch, through the working
  tree, untracked files included.
- **A reader you burn down.** `n` walks to the next unreviewed hunk, `r` marks
  the one you are on and advances.
- **Comments that survive a rewrite.** Anchored to lines, carried through each
  refresh, orphaned rather than silently moved when their code goes.
- **A CLI that answers everything the reader does**, so an agent can read its own
  queue and answer it. `comments --exit-code` gates a hook on whether anything is
  still open.
- **Side by side on `|`**, syntax highlighting, and a tree you can filter.

Sessions are per repo and branch, and resume days later. State lives beside the
repo in SQLite and nothing lands in your working tree.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/praxis-labs-io/zen-review/main/install.sh | sh
```

macOS and Linux on arm64 and amd64. Windows takes the `.zip` from the assets
below. Anything else:

```sh
go install github.com/praxis-labs-io/zen-review/cmd/zen-review@latest
```

[Install](https://github.com/praxis-labs-io/zen-review/blob/main/docs/install.md)
covers the requirements and the PATH setup, and
[the guide](https://github.com/praxis-labs-io/zen-review/blob/main/docs/guide.md)
covers how a review is kept.

## Known gaps

- No Homebrew tap yet.
- The installer does not verify the checksums it downloads. `checksums.txt` is
  published beside the archives if you want to check one by hand.
- A source build reports `dev` rather than a version. Only a release stamps one.
